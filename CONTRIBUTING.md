# Contributing to OpenSideline

Thanks for helping build better community sports technology.

## Quick start

1. Read the README and roadmap.
2. Run `npm start` (Node.js 20+) and `npm test`.
3. For scoring changes, add a test that demonstrates the specific baseball situation first.
4. Make a focused branch and submit a pull request with an explanation, test results and screenshots where UI changes are involved.
5. Keep changes respectful, small enough to review and backward-compatible with the game journal when possible.

## First contribution ideas

- Add scorer test cases: double plays, runners tagging, intentional walks, unusual pitch outcomes.
- Improve mobile/keyboard/screen-reader accessibility.
- Produce a formal definition for public scoreboard event schemas.
- Document different league rule sets without copying copyrighted league publications.
- Audit the prototype for inaccurate statistical assumptions.

## Important rules

- Never include personal data of real minors or proprietary GameChanger code/assets/API tokens in a contribution.
- Don't submit copied source, trademarked assets or unauthorized recordings from another app.
- Identify and discuss any security-sensitive code changes privately using SECURITY.md.
- Follow the CODE_OF_CONDUCT.md.
